# Skill Board 设计文档

日期：2026-10-17

## 1. 为什么要做

用户在多个 AI 编程工具（Claude Code、Codex、opencode、Cursor、Gemini 等）里装了很多 skill。很多是在还没有具体用途时装的，时间一长就忘了自己装过什么。现在有两个需求：

1. **清理**：看出哪些 skill 真正在用，哪些从来没用过。
2. **重新发现**：翻一翻就能想起来“原来装过这个，现在正好能用”。所以每个 skill 的用途必须用中文讲清楚。


## 2. 是什么

一个只在本机使用的 Mac 桌面应用。外壳最初用 Electron，v0.2 起改为 Tauri 2（安装包从约 130MB 降到约 3MB），界面就是一个网页。打开后显示本机所有 skill 的使用排行榜。

### 目标
- 列出本机所有工具里实际装着的 skill，包括全局和项目级，并且去重。
- 每个 skill 显示：名称、中文描述、所属领域、使用次数。
- 能按使用次数从多到少、从少到多排序。
- 能按领域筛选，能搜索。
- 新装的 skill 用 DeepSeek 自动翻译和分类。

### 非目标
- **不新增使用记录方式**：不装 hook，也不做任何实时埋点，只统计现有日志里能找到的数据（用户已明确）。
- 不管理 skill：不安装、不卸载、不编辑。
- 不做详情页，不打开 Finder。
- 不同步、不上传，不做多用户。

### 反目标（技术上能跑，但这样做就算失败）
- 把临时目录、备份目录、插件市场目录里的 skill 当成已安装来展示，导致数量虚高到上千条。用户第一眼看到上千条时的反应就是“我没装这么多”。
- 把“出现在可用 skill 列表里”算作一次使用，导致次数虚高。
- 没填 key 或断网时软件打不开、白屏。

## 3. 数据：扫描哪些 skill

### 3.1 扫描位置
全局：
- `~/.claude/skills`、`~/.claude/plugins/cache`
- `~/.codex/skills`、`~/.codex/plugins/cache`、`~/.codex/vendor_imports`
- `~/.agents/skills`、`~/.cc-switch/skills`
- `~/.config/opencode`（含 `skills`、`superpowers`）
- `~/.cursor`（如 `skills-cursor`）
- `~/.gemini`（如 `antigravity-ide/plugins`）

项目级：在以下目录中查找 `.claude/skills`、`.codex/skills`、`.agents/skills`、`.cursor/skills`、`.opencode/skills` 等子目录下的 `SKILL.md`：
- `~/Development` 下的项目
- Codex 和 Claude Code 会话记录里出现过的工作目录（`cwd`）

跟随软链接，但要防止循环。

### 3.2 必须排除的位置
- `~/.codex/.tmp/` 下的所有内容（插件缓存、`plugins-backup-*`、`bundled-marketplaces` 等）
- 所有 `marketplaces/` 目录：那是可以安装但还没装的插件清单
- `node_modules`、`.git`

另外，插件缓存里**已停用或已卸载**的插件不算已安装：
- Claude Code：以 `~/.claude/plugins/installed_plugins.json` 为准，并且该插件在 `~/.claude/settings.json` 的 `enabledPlugins` 里不能是 `false`。
- Codex：以 `~/.codex/config.toml` 中 `[plugins."<名字>@<来源>"]` 的 `enabled = true` 为准。
- 其他工具没有这类配置，目录里有就算已装。

2026-10-17 实测：原始扫到 1495 个 `SKILL.md`，排除上述位置并对真实路径去重后剩 407 个文件，按 name 去重后 299 个。正常结果应该在这个数量级。

### 3.3 去重规则
- 先按 `realpath` 去重，软链接和原文件算同一个。
- 再按 `SKILL.md` frontmatter 里的 `name` 合并（不区分大小写；没有 name 就用目录名）。合并后一行就是一个 skill，并记录它出现在哪些工具里，用于界面上的工具标签。
- 同一个插件的多个版本缓存（例如 `plugins/cache/<plugin>/<version>/`）只保留最新版本。版本号能比较就按版本号，不能比较就按修改时间。
- 同名但内容不同的 skill（来自不同工具）：描述取最近修改的那份，`SKILL.md` 路径都要保留。

### 3.4 每个 skill 读取的字段
- `name`、`description`：从 frontmatter 读取，要兼容 YAML 多行写法（`>-`、`|`）。实测有 29 个文件的 name 被错误解析成了 `>-`，必须用正规的 YAML 解析器。
- 所在工具列表、全部路径
- 来源：自己装的 / 插件带的 / 工具自带。判断规则：路径在 `plugins/cache` 下的算插件带的；`~/.cursor/skills-cursor`、`~/.codex/skills/.system` 这类算工具自带；其余算自己装的。
- `SKILL.md` 内容的哈希值，用来判断是否需要重新翻译

## 4. 数据：使用次数

原则：**只认“确实打开过这个 skill 的说明”或“明确调用了这个 skill”的记录。** 只是出现在系统提示的可用列表里，不算使用。

通用规则（所有工具都适用）：
- **计数单位是“会话 × skill”**：同一个会话里，不管这个 skill 出现在几个来源、被调用几次，都只算 1 次。所以跨来源去重靠会话 ID：Claude 的 `history.jsonl` 带 `sessionId`，Codex 的 `history.jsonl` 带 `session_id`，都能和会话记录对上。
- **记录归属**：先用路径归属。日志里出现 `.../<目录>/SKILL.md` 时，用扫描阶段建立的“realpath → skill”和“目录名 → skill”映射找到对应的 skill；路径对不上时，再按名字匹配（去掉 `插件:` 前缀，不区分大小写）。都对不上的，比如已删除的 skill，丢弃不计。
- **不同插件里的同名 skill 合并成一行**，次数相加。这和“按名字去重”一致，用户要的是不重复。
- **累计保留**：使用记录（会话 ID、skill、工具、时间）一旦解析出来就永久保存在本地。即使原始日志后来被工具自动清理，次数也不会减少。“重新扫描”只重扫 skill 列表和新增日志，不清空已有的使用记录。

### 4.1 Codex（主要来源）
- 位置：`~/.codex/sessions/**/*.jsonl`，记录从 2025-10 开始，目前约 2.7G、91 个文件。
- 统计 `type` 为 `response_item`、且 payload 类型是 `function_call` / `custom_tool_call` / `local_shell_call` 的行，看参数里有没有出现 `skills/<名字>/SKILL.md`。
- 同一个会话里多次读取同一个 skill，**算 1 次**。（我的决定：一次任务里反复读同一个文件不应该放大次数。实测 ego-browser 按调用数是 39，按会话数会更少。）
- 用户在 Codex 里用 `$skill名` 显式调用的记录（`~/.codex/history.jsonl`），如果能可靠识别，也算进去，同一会话内去重。

### 4.2 Claude Code
- `~/.claude/projects/**/*.jsonl`（递归查找，包括子代理目录）里 `name == "Skill"` 的工具调用，取 `input.skill`（会带插件前缀，如 `superpowers:brainstorming`，匹配时去掉前缀）。只有最近一个月左右的数据。
- 同一批日志里用 Read、Bash 等工具读取 `SKILL.md` 的调用也算，口径和 Codex 一致。
- `~/.claude/history.jsonl` 里用户手动输入的 `/命令`，只统计能对上 skill 名的那些（`/login`、`/model` 这类内置命令不算）。
- 同一会话内去重。

### 4.3 其他工具
opencode、Cursor、Gemini：由开发者自行调查有没有可用的本地会话记录。有的话按同样原则统计；没有的话，这些工具贡献 0 次，不影响其他工具的统计。

### 4.3.1 实现备注（v0.1）
- Codex 较老的会话会被压缩成 `.jsonl.zst`（实测 564 个，2.7G 中的大部分），用 Node 自带的 zstd 解压读取。
- opencode（`~/.local/share/opencode/opencode.db`）、Cursor、Gemini 的使用记录暂未接入，这些工具目前贡献 0 次。

### 4.4 输出
每个 skill 输出：总次数（各工具相加）、每个工具分别的次数、最近一次使用时间。最近使用时间先存下来，界面暂时不显示。

### 4.5 增量缓存
会话日志很大，必须做增量：缓存里记录每个日志文件已解析的大小和修改时间，下次只解析新文件或文件新增的部分。第一次全量扫描时界面要显示进度，不能卡死。

## 5. 翻译和分类（DeepSeek）

- 设置页：填 DeepSeek API key。预先填好 Base URL `https://api.deepseek.com` 和模型 `deepseek-chat`（OpenAI 兼容接口），两者都可以修改。key 保存在本机，优先放进 macOS 钥匙串。
- 每个 skill 需要两个结果：**中文描述**（一两句话说清楚它干什么、什么时候用，不要逐字直译）和**领域**（从固定列表中选一个）。
- 固定领域列表（我的决定，开发时可以根据实际 skill 微调，但必须是固定集合）：浏览器自动化、飞书/办公协作、文档处理（PDF/Word/Excel/PPT）、图片生成与处理、视频与音频、内容写作与发布、设计与前端、开发工具与工作流、知识管理（Obsidian/笔记）、数据与可视化、AI/模型接入、其他。外加“未分类”，表示还没处理或处理失败。
- 批量处理：每次请求送多个 skill，要求返回 JSON。并发数要有限制，失败的条目要能重试。
- 缓存：按 `name + SKILL.md 哈希` 缓存结果。只有新 skill 或内容变了的 skill 才重新请求。
- 领域列表可在设置里自定义（每行一个，顺序即左栏顺序）。删掉某个领域后，属于它的 skill 自动重新分类；手动编辑过的不动。
- 第一次填好 key 后，自动处理全部约 300 个 skill。之后每次启动扫描完成后，只处理新增或变化的。
- 没有 key、请求失败或断网时：显示英文原描述，领域显示“未分类”，其他功能照常。

## 6. 界面（用户选的方案 A：左侧领域栏）

- **左栏**：第一项是“全部”，下面是各个领域，每项后面显示数量。点击后只显示该领域。
- **顶部**：搜索框，同时匹配名称、中文描述、英文描述，输入即过滤；“使用最多 / 使用最少”切换按钮；一个“设置”入口；一个“重新扫描”按钮（我的决定）。
- **列表**：每行依次是排名、名称、中文描述、领域标签、使用次数。
  - 名称下面用小标签显示所在工具（Codex / Claude / opencode / Cursor / Gemini…），再用一行小灰字显示来源（自己装的 / 插件带的 / 工具自带）。
  - 次数为 0 时数字变淡。
  - 排序：先按次数，次数相同再按名称。
  - 点击行弹出编辑框：显示英文原描述，可手动修改中文描述、从下拉框选分类，也可以点“让 AI 重新生成”。保存后标记为“已编辑”，之后自动翻译不再覆盖。
- 状态提示：扫描中、翻译中（已完成数 / 总数）、未配置 key。
- 界面全部用中文。

## 7. 技术约束

- Tauri 2：界面是 `renderer/` 下的静态网页，后台（扫描、统计、翻译、存储）用 Rust 写在 `src-tauri/`。Tauri CLI 装在项目本地 `node_modules`，不做全局安装（用户的全局规定）。
- 缓存文件放在应用数据目录；API Key 放在 macOS 钥匙串。
- 最终产出一个能双击打开的 `.app`。只给自己用，不需要签名、公证和自动更新。

## 8. 交给开发者自行决定的部分
- 前端是否使用框架、具体样式。保持简洁，跟随系统深色/浅色模式。
- 缓存的格式（JSON 或 SQLite）。
- DeepSeek 每批处理多少条、并发数多少、提示词怎么写。
- 其他工具使用记录的具体解析方式（见 4.3）。

## 9. 由我（Claude）做的决定，供用户核对
- 同一会话内多次读取同一个 skill 只算 1 次。
- 固定的领域列表（第 5 节）。
- 第一次填好 key 后，由软件自动全量翻译，不手工预翻。
- 来源标签（自己装的 / 插件带的 / 工具自带）只展示，不能筛选。
- 增加“重新扫描”按钮。
- 最近使用时间先存下来，界面上不显示。
- 使用记录累计保留，原始日志被清理后次数不减。
- 已停用或已卸载但缓存还在的插件，不算已安装。
- Claude Code 里直接读取 `SKILL.md` 也算一次使用，和 Codex 口径一致。
- 不同插件里的同名 skill 合并成一行，次数相加。
